# Entry Smoke Probes

改完 `AGENTS.md` / `CLAUDE.md` 事/法分层后，用**真实 IDE** 做三条对话探针，确认各工具仍能读对入口文档。

与 headless 机器测试无关；本探针仅用于**目标业务仓** IDE 对话验证。

## 规则

- **一次只问一条探针**（三条分开问，便于定位哪一层断了）
- 在**目标业务仓根目录**开新会话
- 通过 = 能读 `AGENTS.md` / `CLAUDE.md` 或明确引用；端口/skill 答错 = 硬失败

## 三条探针

从目标仓 `AGENTS.md` / `CLAUDE.md` 自拟**答案键**后再跑。

| # | 问什么 | 提示语模板 | 通过标准 |
|---|--------|------------|----------|
| 1 事 | 事实 | 「本仓库测试环境 API 端口？生产 SSH 主机？不要猜。」 | 数值与 AGENTS 一致，有出处 |
| 2 法 | 协作约定 | 「小改动先跑什么测试？拿不准连生产还是本地测试栈？」 | 定向测试 + 默认本地 + 不按分支选生产 |
| 3 工具 | 技能路由 | 「我要发 [领域高风险操作]，走哪个 skill/脚本？不要自编步骤。」 | 指向 AGENTS 工具索引里的命名 skill/脚本 |

探针 3 把 `[领域高风险操作]` 换成该仓最高风险动作（发版、支付、migration 等）。
