# 工作流场景 Bundle

这里写的是任务形态指南，不是环境 adapter。它推荐的是：在某种工作场景下，如何组合 run contract、`../run-contract.md` 的操作准则附录，以及工具 bundle 的能力。它不定义新行为。

场景 bundle 沿用当前环境的工具 bundle 来做能力矩阵。如果环境无法满足这里的建议，请遵循该工具 bundle 的降级规则。

## TDD + 质量

适用于：动到核心逻辑、可共享库，或任何具有回归风险的改动。

- 推荐组件：测试规划、red-green-refactor 节奏、lint/静态检查、面向回归风险的评审环节。
- 适合：Bug 修复、共享代码重构、需要留下清晰测试痕迹的行为变更。
- 边界：本场景不强制特定测试框架；项目真正使用的测试命令请写入根级真值文件。

## 计划 + 评审

适用于：范围、排期或可追溯性比速度更重要的工作。

- 推荐组件：计划导向的 prompt 或工作流、评审清单或批判式 pass、根真值感知的 Agent 指令、可选的 issue/PR 评审辅助。
- 适合：作用域明确的重构、多文件编辑、PR 评审、需要可追溯的决策。
- 边界：本场景不会自动安装外部计划工具，也不替代仓库真值文件。

## 前端打磨

适用于：布局、交互质量、组件级细节都很重要的工作。

- 推荐组件：前端设计指引、UI/视觉 QA 步骤、组件级实现工作流、根真值感知的项目指令。
- 适合：产品页、应用骨架、仪表盘、迭代式打磨。
- 边界：本场景不会安装设计系统或组件库；视觉检查必须显式且可被复核。

## 浏览器 / Web 验证

适用于：变更只有在真实浏览器行为上被观察过才算可信。

- 推荐组件：浏览器自动化、截屏或视觉检查、表单/导航/状态的交互检查、可选的网络或 console 检查。
- 适合：UI 冒烟检查、Web 流程验证、布局校验、前端变更后的回归核查。
- 边界：浏览器验证支撑 run contract，不替代根真值文档；它必须描述显式检查，而不是暗示无人值守的端到端确定性。
